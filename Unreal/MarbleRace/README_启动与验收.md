# 弹珠竞速 UE5 原生工程

## 当前交付状态

本目录包含可交给 UE5 工具链处理的 C++ 工程源码、配置和编辑器场景生成脚本。当前电脑未检测到 UE5，因此**尚未编译或运行验证，不是已打包的游戏**。

浏览器原型保留在原工作区，后续主开发以本工程为准。

## 已编写

- 约 5.2 米赛道；16 mm 球形弹珠；厘米、秒、千克单位体系。
- 连续左右曲折的地板与侧壁，静态三角网格碰撞；不再使用独立短板拼接碰撞。
- 双侧贴墙金属漏斗；出口内侧净宽 35 mm，两颗 16 mm 弹珠并行可通过，余量 3 mm。
- 错位木钉、交替斜向挡板、终点；后续障碍保留明确通路。
- Chaos 球形刚体，CCD 与物理子步进，重力加速、摩擦和恢复系数。
- 开赛时从静止释放，不给隐藏推力，不按名次补速，不强行传送脱困。
- 鼠标拖动/缩放进入自由镜头并保留位置；F 恢复跟随；Tab 切换关注。
- 计时、关注弹珠与排名的调试 HUD。
- 透明彩色、星空、银河、火焰、棒棒糖旋涡的材质生成脚本；所有碰撞形状仍是球体。
- Lumen、Virtual Shadow Maps、TSR、DX12/SM6 与硬件光追支持配置。

## 启动步骤

1. 安装 Unreal Engine 5.4 或以上的稳定版本；团队锁定同一小版本。
2. 安装 Visual Studio 2022 的“使用 C++ 的游戏开发”、MSVC 和 Windows SDK。
3. 打开 `MarbleRace.uproject`，使用已安装的引擎关联项目并生成工程文件。
4. 构建 `MarbleRaceEditor / Development Editor / Win64`。出现版本/API 问题时需按实际引擎版本修正，不能跳过编译错误。
5. 首次缺少 `/Game/Maps/Workshop` 时，进入空白关卡。
6. 编辑器启用 Python 插件（工程已声明），在 Python 控制台执行下列命令，将路径改为本工程绝对路径：

```python
exec(open(r'C:/Users/yzlit/Documents/Codex/2026-09-16/https-www-bilibili-com-video-bv1wimbbmeaa/outputs/Unreal/MarbleRace/Tools/GenerateWorkshop.py', encoding='utf-8').read())
```

7. 打开 Workshop 关卡，按 Play；按 Space 开始比赛。

生成脚本会保留已有材质和地图，避免覆盖手工美术工作。赛道与参赛球在游戏开始时由 GameMode 生成，编辑器非运行状态暂时只显示房间。

## 物理说明

采用真实单位：重力为 980 cm/s²，初始坡度约 7.4°。实心球无滑动滚动时理论加速度约为 `5/7 × g × sin(坡角)`，并非直接等于重力沿坡分量；摩擦、碰撞和滚动阻力会进一步改变结果。当前质量统一为 6 g，用于比较外观；金属球也采用认证质量，尚未模拟不同材质密度的竞技差异。

子步进最大步长为 1/240 秒，最多 16 步；这不是跨平台严格确定性承诺。低于约 15 FPS 时不能假定仍维持该精度。HUD 暂用游戏时间计时，不作为亚毫秒级正式赛事判定。

官方依据：[物理子步进](https://dev.epicgames.com/documentation/unreal-engine/physics-sub-stepping-in-unreal-engine)、[静态复杂碰撞与动态简单碰撞](https://dev.epicgames.com/documentation/unreal-engine/simple-versus-complex-collision-in-unreal-engine)。程序化地板为静态复杂碰撞，弹珠使用动态简单球形碰撞，符合该使用方式。

## 第一轮验收清单

1. 30/60/120 FPS 下分别跑 20 场，记录穿模、逃逸和未完赛数量。
2. 测量漏斗入口侧边能否绕行；用两球并行验证喉部；用三球验证拥堵后能自然释放。
3. 每个木钉通道间距、挡板逃逸通道和弯道净空均需通过测量复核。
4. 三种初始坡度做实体台对照：测量通过 50 cm 的时间、反弹高度和滑移。
5. 连续自由旋转、缩放 10 秒，确认无自动复位；按 F 后才恢复跟随。
6. 对透明球、星空和旋涡球录制近景运动，检查反射闪烁、透明排序和 UV 接缝。
7. 之后再添加最终静态美术资产的 Nanite、扫描 PBR 与电影镜头；必须录制实机证据。

## 网页与概念图的关系

高配置电脑上的浏览器可以在受控场景中逼近写实截图，但当前浏览器原型明显达不到概念图。高速动态、透明折射、球间反射、室内间接光照和广泛设备适配会扩大差距。没有同场景实测，不能用百分比描述画质接近程度。

如果最终仍要在网页访问，同时保留 UE5 画质，评估 Pixel Streaming：UE5 在 GPU 主机运行，网页接收视频并发送操作。该方式需要持续计算资源、服务部署和网络延迟预算；不是浏览器原生渲染。首阶段先验证本地 UE5。
